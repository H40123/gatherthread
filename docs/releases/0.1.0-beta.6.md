# GatherThread 0.1.0-beta.6 — Beta 6

Beta 6 combines the reviewed main-branch updates from PRs #124, #126 and #127:
the Team canvas, workspace motion and contrast, portable JSON configuration,
guided Team setup, empty Solo cleanup and Launcher connection improvements.
Publication records and deployment receipts establish availability; these notes
alone do not.

## Changes

- Configure Agent Teams on a canvas or start from a preset. Select the exact
  Agent for each module, review its links and budget, then save, test and enable
  the Team through the existing controls.
- Import/export versioned JSON for browser preferences and Team definitions.
  Published JSON Schemas, examples and the `gatherthread-config` skill support
  editor and Agent assistance. Imports create editable settings or Team drafts;
  they do not grant sharing permissions, activate a Team or start a task.
- **Let AI configure** opens a private Solo with a prepared, unsent prompt. Valid
  Team JSON in the reply can be previewed before applying it. A newly created
  Solo with no submitted message is cleaned up when leaving it; existing
  messages, concurrent writes and empty Multi conversations are preserved.
- Refine button feedback, panel transitions, glass surfaces and message colors.
  Hover/focus text, touch gestures and reduced-motion paths remain usable.
- Improve Launcher connection recovery and disconnect handling, retain exact
  runtime ownership during process replacement, and add branded presentation.

See [JSON configuration](../CONFIGURATION.md) and
[Agent Team configuration](../AGENT_TEAM_CONFIGURATION.md) for the supported
fields, draft workflow and preset behavior. Team execution remains a bounded
preview with exact-target permissions and explicit controls; this release does
not enable unrestricted autonomous collaboration or Claude Code Team modules.

not configure a provider, broaden an execution grant or start a task.

## Upgrade and verification

Update server and Web together from one fixed reviewed main commit. Preserve
independent test/production accounts, databases, secrets, test admission and
configuration. Take verified backups before startup migrations and bind the
effective static directory to the new release. Never roll back databases after
migration to make an older application start.

Record application source, npm packages, Launcher archives and hosted container
provenance separately. Reuse a hosted image only after confirming its build
inputs are unchanged, retaining its original immutable image ID and source;
never relabel an older image as a Beta 6 build. New download archives record the
actual Beta 6 source commit, versions and checksums.

Use the canonical release gate and the current Windows/Linux/macOS CI. Reuse
the reviewed changes' existing browser/native verification; deploy the same
verified Linux candidate to test then production through the existing operator
entry. Do not rebuild, repeat the full tests or call real models on either
server. Record package publication, installed-app checks, host activation and
business/provider E2E as separate evidence.
