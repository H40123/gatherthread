# GatherThread 0.1.0-beta.4 — Beta 4

Beta 4 brings the reviewed main-branch updates after Beta 3 into matching server,
Web, npm, plugin and Launcher artifacts. The authorized rollout updates both
`test.gatherthread.cn` and `gatherthread.cn` from one frozen Linux build, retaining
their independent accounts, data, configuration and secrets. Published artifacts
and deployment receipts establish availability; these notes alone do not.

## Highlights

- Preview saved Agent Teams: configure connected Agents as modules, test the
  exact configuration, then explicitly enable it and request a bounded task.
  Supported own Codex/DSH connections, explicitly shared native connections and
  eligible cloud profiles retain their exact device/model/permission boundaries.
  Delegations run serially within call/time budgets, with independent Pause/Stop
  and recoverable receipts. This is a bounded preview, not unrestricted or
  general-purpose autonomous collaboration. See
  [ADR-0061](../adr/0061-account-private-saved-agent-teams.md).
- Connect Claude Code using the matching Launcher, standalone npm connector and
  native plugin. Use native commands/MCP tools, separately reviewed Hooks,
  per-conversation upload consent and streamed public work. Requests to your own
  Claude Code can use terminal commands and dependency installation under the
  local Claude permission policy; GatherThread does not add a separate read/write
  tool-only restriction. Private-output and owned-process controls still apply.
  Claude Code is not a native Agent Team node in this preview. See
  [Claude Code setup](../CLAUDE_CODE.md) and
  [ADR-0060](../adr/0060-claude-code-plugin-and-local-connector.md).
- Keep the file-workspace example and bilingual guides aligned with the right
  file panel: inspect the demo's real source, previews, changes and working result
  without contacting a backend or consuming model quota.
- Include native execution cancellation, confirmed-exit recovery before session
  discovery, reconnect-time emergency controls and stale-diagnostic fixes. Keep
  safe capacity holds until exact exit evidence is acknowledged; losing a process
  or deleting a session is not exit proof. Patch Zod to `4.6.6` without changing
  the validated protocol shapes or request limits. Update server and hosted-image
  Undici from `7.30.0` to `7.30.1` for the upstream denial-of-service and integrity
  fixes, including [GHSA-xjj6-f33q-929c](https://github.com/advisories/GHSA-xjj6-f33q-929c).

The existing mobile redesign, file editing/previews, opt-in connection sharing,
personal APIs, cloud trial and cloud GitHub tasks remain available under their
existing authorization and configuration. Neither a release nor a model label
grants additional access, configures a provider or starts an Agent.

## Upgrade and evidence boundaries

Upgrade server and Web together. Before startup migrations, take each
environment's independent SQLite/cloud-Git backup using the existing reviewed
operator. The new Team/run/receipt and native-execution state must not be erased
or reset by an upgrade. Preserve the existing model, registration, GitHub App,
container, test-admission and resource configuration. Prefer forward repair
after migration rather than starting an older binary against changed stores.

Resolve the process's effective `GATHERTHREAD_STATIC_DIRECTORY`, not an assumed
`current/apps/web/dist`. This upgrade must bind the effective static root to the
new release so the public Web files and backend belong to the same batch.
Validate the installed maintenance-lock contracts without changing permissions
merely to satisfy a generic checker. Use the upgrade operator, not the fresh-host
installation instructions, on existing services.

Reuse the reviewed feature tests and latest CI. Run the canonical release and
Git-less package checks once on the frozen source; a source-identical Linux
build may reuse those results with explicit source/tree/build provenance. Do
not rerun the whole test campaign or model diagnostics on each server. The host
handoff requires artifact checksums, backup receipts, release/PID identity,
loopback and public HTTPS readiness, and exact public static-file provenance.

The Undici patch changes the hosted-image build input, so Beta 4 requires a new
image with its own immutable image ID and source provenance; do not reuse or
relabel the old Beta 3 image. Keep the existing runtime, model and resource
configuration, changing only its verified image identity. No new real-provider, native
account, GitHub OAuth or operating-system acceptance is implied by fixture/CI
results. Record any such checks separately when they actually run.
